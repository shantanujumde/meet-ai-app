## Description

Search across every meeting, transcript, note and ticket. The index lives at `~/Meetings/.app/index.db`.

The gate here is the interesting part, and it is the L7 invariant stated as a test: **delete `index.db`, and everything still works after a rescan.** Not "mostly works". Identical results, same meetings, same tickets, same search hits. If anything is only in the database, the markdown has stopped being the source of truth and the product's core claim is gone.

FTS5 availability is already proven — `crates/store` has a test that fails loudly if the bundled SQLite was built without it, precisely so Phase 3 does not discover this the hard way.

#### Scope

- Index meetings, transcripts, notes and tickets on a full scan, and keep it current from the 3b watcher.
- A search box in the app. Results readable at a glance, and they open the thing they point at.
- Rebuild from scratch when the index is missing, corrupt, or from an older schema. The `Error::Index` variant already in `store` says "always recoverable: delete and rescan" — make that literally true rather than aspirational.
- No semantic search. That is L8, deferred on purpose.

#### Gate

`rm ~/Meetings/.app/index.db && just dev` → every meeting, ticket and search result comes back identical. Run it with a folder that has real content in it, not three fixtures.
