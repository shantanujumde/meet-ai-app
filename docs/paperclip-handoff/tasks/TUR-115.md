#### Steps

1. Confirm (or provision) a local codesigning identity: `security find-identity -v -p codesigning` should list "meet-ai Local Signing". If it does not, run `bash spikes/phase0a-tcc/make-identity.sh` (see `RELEASING.md` for background) — it is headless, no sudo, and only touches a dedicated `meet-ai-signing.keychain-db`.
2. `just bundle-signed` — builds, signs, and verifies the app bundle. `tauri dev` does not prove anything about capture, so this step is not optional.
3. Launch `target/release/bundle/macos/meet-ai.app`. Complete onboarding if this is a fresh install, so audio permission is actually granted (Granted, not just Unknown).
4. Press Record (the titlebar button or ⌘⇧R), talk for about a minute while playing some system audio (e.g. a video or music), then press Stop.
5. In the resulting meeting folder under `~/Meetings/<id>/audio/`, confirm `mic.wav` and `system.wav` are both non-empty and play back with the right content on the right track (your voice on mic, the played audio on system).
6. Run `cargo run -p audio --bin drift-check -- ~/Meetings/<id>/audio/` and confirm it passes.
7. Revoke audio permission in System Settings (Privacy & Security → System Audio Recording Only, and Microphone), relaunch the app, and try to record. Confirm: recording is refused with a clear on-screen reason (not a raw error code), and no new empty meeting folder is left under `~/Meetings/`.

Code under test: `src-tauri/src/recording.rs` (start/stop + permission backstop), `src-tauri/src/commands.rs` (`toggle_recording`/`stop_recording`), `src-tauri/src/lib.rs` (⌘⇧R handler). Commit: 02b400d on branch `docs/releasing-guide`.
