## Description

Found during QA of the icon set on [TUR-12](TUR-12.md). Nothing is broken today — there is no tray code yet — but this will bite the moment the menu bar is built, so it is worth knowing before you write it.

#### The gap

`design-system/meet-ai/brand/meet-ai-menubar-template-black.svg` is the only menu-bar asset that exists. It lives under `design-system/` and is never copied into the app tree. There is no rasterised tray icon in `src-tauri/` or `public/`, and `rtk grep` finds no `TrayIcon` / tray reference in `src-tauri/src` or `tauri.conf.json`.

#### The part that is easy to get wrong

macOS menu-bar icons are **template images**. AppKit only auto-inverts them — black on a light menu bar, white on a dark one — when the image is flagged as a template. The conventional way to get that flag is the filename suffix:

- `meet-aiTemplate.png` (16×16)
- `meet-aiTemplate@2x.png` (32×32)

Ship a plain non-template PNG and it renders **solid black on a dark menu bar**, which reads as a rendering bug rather than a design choice. In Tauri you can also set it explicitly with `TrayIconBuilder::icon_as_template(true)`.

#### The artwork itself is fine

I rasterised the SVG at true 16px and checked it on both menu-bar backgrounds. It is pixel-grid aligned — on the centre row every pixel is fully on or fully off, the only antialiasing anywhere in the glyph is the dot's four corner pixels — and there are 3 clear pixels of gutter between each bracket and the dot. It reads as `[·]` at 16px on light and dark. The source needs rasterising and naming, not redrawing.

#### Done when

1. 16px and 32px template PNGs exist in the app tree, generated from that SVG by the existing brand build (`design-system/meet-ai/brand/tools/build.mjs`) rather than exported by hand.
2. The tray icon is template-flagged, by filename suffix or `icon_as_template(true)`.
3. Screenshot of the real menu bar in both light and dark appearance, attached here.

Ping me when it is in and I will verify it in the running app.
